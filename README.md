# wworld — генератор подземелий (Pascal + R)

Модуль строит подземелье из комнат разной формы, соединённых коридорами трёх
рангов, сохраняет его графом-инструкцией в JSON и даёт ходилку по результату.
Генерация детерминирована: одинаковый seed даёт побайтово одинаковые файлы.

Хранится не растр, а то, из чего он однозначно выводится: seed,
спецификации форм комнат, осевые линии коридоров с рангом, узлы развилок,
связи и лестницы. Клетки строятся заново геометрией на R при чтении. CSV
остаётся человекочитаемой выгрузкой для проверки глазами и валидатором и
пишется только с флагом `--test`.

Работа поделена по сильным сторонам языков. Геометрию считает R: комната —
логическая матрица-маска, коридор — вектор клеток, кисть — вектор смещений;
там, где Pascal писал бы двойной цикл, в R стоит одно векторное выражение.
Pascal держит сетку, занятость клеток, поиск маршрута и правила прогрессии.
Генератор поднимает `Rscript scripts/geometry.R` одним постоянным процессом и
разговаривает с ним построчно через каналы, поэтому **Rscript обязателен для
генерации**, а не только для проверки.

## Сборка и запуск

```sh
sudo apt-get install -y fp-compiler fp-units-base fp-units-fcl r-base-core
git submodule update --init --recursive

fpc -Mobjfpc -Sh -O2 -Fusrc/dungeon -FUsrc/dungeon -osrc/demo/demo   src/demo/demo.pas
fpc -Mobjfpc -Sh -O2 -Fusrc/dungeon -FUsrc/dungeon -osrc/demo/wwwalk src/demo/wwwalk.pas

./src/demo/demo --seed 20260813 --levels 10 --out out          # граф в out/dungeon.json
./src/demo/demo --seed 20260813 --levels 10 --out out --test   # плюс выгрузка out/csv
Rscript scripts/validate_dungeon.R --dir out/csv               # проверка инвариантов
./src/demo/wwwalk --json out/dungeon.json                      # ходьба по графу
./src/demo/wwwalk --dir out/csv                                # ходьба по выгрузке
```

Генерация требует `Rscript`. Ходьба по графу — тоже: карта из него строится
заново. Ходьба по выгрузке CSV обходится без R, там лежит готовый растр.

Флаг `--test`, кроме выгрузки, включает сверку обратной сборки: записанный
JSON перечитывается с диска, карта строится заново и сравнивается с исходной
клетка в клетку. Расхождение означает, что графа для восстановления не
хватает, и прогон завершается с кодом 3.

Ходьба: `WASD` и `QEZC` (диагонали), `>` и `<` на клетке лестницы, `Esc` — выход.
Неинтерактивный прогон: `--script "ddssww>"`.

### BearLibTerminal

Биндинг берётся из сабмодуля `third_party/bearlibterminal` (форк
`Risto90/bearlibterminal`), правки в него вносятся там же. Биндинг линкуется
статически, поэтому графический бэкенд включается отдельно и требует
`libBearLibTerminal.so` рядом с бинарником:

```sh
fpc -dUSE_BLT -Mobjfpc -Sh -O2 -Fusrc/dungeon \
    -Futhird_party/bearlibterminal/Terminal/Include/Pascal \
    -osrc/demo/wwwalk src/demo/wwwalk.pas
```

Без `-dUSE_BLT` собирается терминальный бэкенд — он же работает в CI.

## Прогрессия этажей

| этаж | комнаты | что добавляется |
|---|---|---|
| 1–2 | малые | только побочные коридоры (1 клетка) |
| 3 | + средние | первый второстепенный коридор (2 клетки) между средними комнатами |
| 5 | + большая | первая большая комната |
| 6 | | первый главный коридор (3 клетки) |
| 8 | | составные формы комнат |

Количество комнат считается по формуле и дополнительно режется общим
бюджетом этажа (`10 + 3×этаж`), где малая стоит 1, средняя 3, большая 6.
Потолки: 10 малых, 5 средних, 3 больших.

Размеры (максимальная сторона или больший диаметр): малая 5, средняя 8,
большая 10. С шестого этажа максимум одного из типов растёт на 1 в порядке
большая-средняя-большая-средняя-большая-малая; минимумы не меняются.

Ширина коридора соответствует наибольшей из связываемых комнат, но не выше
ранга, разблокированного на этаже. От главного коридора отходят
второстепенные, от второстепенных — побочные. Один конец главного или
второстепенного коридора может упираться не в комнату, а в узел-развилку, из
которого расходятся два коридора рангом ниже.

Длина коридора не превышает удвоенной большей стороны большей из
связываемых комнат (но не меньше 10 клеток — иначе на малых комнатах
маршрут не находится).

## Как исключены две ошибки

Обе — по построению, а не проверкой постфактум.

**Наложения.** Каждая клетка занимается только через `TWwGrid.CanOccupy`,
который требует, чтобы сама клетка и все 8 её соседей были свободны либо
принадлежали явно разрешённому набору структур. Поэтому между чужими
элементами всегда остаётся минимум клетка монолита, а всякое касание —
только запланированное: портал комнаты, узел развилки, отмеченное
пересечение коридоров.

**Несвязность.** Граф строится остовно: новая комната фиксируется только
после того, как к ней успешно проложен коридор от уже связанной структуры;
не проложился — комната стирается и место выбирается заново. Циклы и
развилки только добавляют рёбра. В конце делается заливка от лестницы вверх
и сверяется охват со всеми проходимыми клетками; при расхождении этаж
перегенерируется с производным seed.

Валидатор на R проверяет то же самое независимо, читая только CSV.

## Форматы

### JSON — основное хранилище

`out/dungeon.json` описывает подземелье графом:

```json
{ "format": "wworld-dungeon", "version": 1, "seed": "20260813",
  "levels": [ { "level": 8, "width": 50, "height": 63,
    "stairs": { "up_x": 6, "up_y": 24, "down_x": 41, "down_y": 55 },
    "rooms": [ { "shape": "composite", "kind": "large", "id": 1, "x": 2, "y": 21,
                 "parts": [ { "type": "rect", "w": 4, "h": 5, "ox": 0, "oy": 0 },
                            { "type": "circle", "w": 6, "h": 6, "ox": -5, "oy": 0 } ] } ],
    "corridors": [ { "id": 3, "rank": 3, "from": 1, "to": 2,
                     "path": [ [10, 25], [11, 25] ] } ],
    "forks": [ ... ], "links": [ { "a": 1, "b": 3, "kind": "portal" } ] } ] }
```

Маски комнат и клетки коридоров не хранятся: их считает геометрия на R по
спецификации и осевой линии. Граф вдвое компактнее растра и, в отличие от
него, читается как замысел, а не как результат.

Порядок восстановления повторяет порядок построения — по возрастанию
идентификатора, а он выдаётся строго по ходу генерации. Поэтому
восстановленная карта обязана совпасть с исходной клетка в клетку, что и
проверяет `--test`.

### CSV — тестовая выгрузка

Пишется только с `--test`, в `out/csv/`. В CSV нет вкладок, поэтому лист —
это файл, а `index.csv` играет роль оглавления книги.

- `level_NN.csv` — матрица кодов клеток, строка = ряд карты;
- `level_NN_owner.csv` — матрица владельцев (id структуры или −1);
- `index.csv` — этажи, размеры, seed, координаты лестниц;
- `rooms.csv`, `corridors.csv`, `links.csv` — паспорта структур и связей.

Коды клеток: 0 монолит, 1 стена, 2 пол комнаты, 3 побочный коридор,
4 второстепенный, 5 главный, 6 пересечение, 7 узел развилки,
8 лестница вверх, 9 лестница вниз.

Готовые карты в репозитории не лежат: они однозначно выводятся из seed.
Собранный набор публикуется артефактом `dungeon` успешного прогона CI; если
прогон упал, вместо него выкладывается `failure-logs` с пошаговыми логами.

## Устройство

```

  wwCore.pas       типы, детерминированный ГПСЧ (xorshift128+), контейнеры
  wwShapes.pas     форма комнаты — готовая маска из R, своей геометрии нет
  wwRGeom.pas      клиент геометрического сервера: канал, разбор, кеш
  wwGrid.pas       сетка, владельцы клеток, правило занятия
  wwStruct.pas     комнаты, коридоры, развилки, связи, уровень
  wwRules.pas      прогрессия этажей
  wwRouter.pas     A* по 8 направлениям, кисть прикладывается готовая из R
  wwGenerator.pas  сборка уровня и инварианты
  wwJson.pas       основное хранилище: запись и чтение графа
  wwRebuild.pas    восстановление растра из графа
  wwCsv.pas        тестовая выгрузка и её чтение
  wwSource.pas     источник карт для ходилки: граф или выгрузка
  wwViewer.pas     ходилка: терминал и BearLibTerminal
src/demo/          demo (генерация), wwwalk (ходьба)
scripts/
  geometry.R           геометрия: маски комнат, кисти, развёртка коридоров
  validate_dungeon.R   независимая проверка выгруженных CSV
```

### Протокол геометрии

Одна строка — один запрос, ответ тоже строкой:

```
SHAPE rect W H | SHAPE square S | SHAPE ellipse W H | SHAPE circle D
COMPOSITE N t w h ox oy [...]     -> OK W H METRIC <маска 0/1 по строкам>
BRUSH R                           -> OK N dx dy ...
EXPAND R N x y x y ...            -> OK M x y ...
PING -> OK PONG | QUIT
```

Случайности на стороне R нет: все ответы — чистые функции аргументов,
розыгрыш размеров и смещений остаётся за ГПСЧ на Pascal. Поэтому ответы
безопасно кешируются (за прогон из 10 этажей около 400 запросов и 1000
попаданий в кеш) и seed по-прежнему воспроизводится побайтово.

Весь код — методы классов, свободных процедур и функций нет ни в Pascal, ни
в R. (Метод, возвращающий значение, в Pascal синтаксически объявляется
словом `function` — иначе класс не написать.)

## Принятые решения

Места, где буквальное требование пришлось разрешить:

1. Большая комната появляется на 5 этаже, а главный коридор — на 6. Ширина
   коридора ограничена рангом этажа, поэтому на 5 этаже к большой комнате
   ведёт второстепенный коридор.
2. «Каждый этаж на отдельном листе»: CSV листов не имеет, поэтому лист = файл
   плюс `index.csv` как оглавление. Если нужны настоящие вкладки — это xlsx,
   экспортёр добавляется отдельно.
3. Нижняя граница длины коридора поднята до 10 клеток: для малой комнаты
   удвоенная сторона даёт 6–10, и на таком поводке маршрут вокруг соседних
   структур часто не находится.
4. Розыгрыш размеров и смещений частей остался на Pascal, хотя это тоже
   «про геометрию». Иначе пришлось бы держать второй генератор случайных
   чисел на стороне R и синхронизировать его — воспроизводимость по seed
   этого не переживёт. R получает уже разыгранные параметры и строит по ним
   форму.
5. Ходьба по основному хранилищу требует R, потому что растра в нём нет.
   Это плата за хранение замысла вместо результата; если R под рукой нет,
   есть выгрузка CSV — она самодостаточна.
